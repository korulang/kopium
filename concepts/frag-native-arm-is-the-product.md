# The transliterated arm was scaffolding, not product — measure the arm that ships

The generated `airline_tools.k` surface (tau2 JSON schemas -> ok/error
string procs -> callIO) was never the product. It transliterates a
foreign tool-call convention into Koru syntax while stripping every
Koru advantage: typed bindings, obligation handles, progressive
disclosure. A week of fixes — exemplars, guides, enforcement guards,
placeholder checks — patched symptoms of an untyped boundary.

The native arm (`airline_native.kz`, `KOPIUM_SCOPE=airline-native`)
carries the real design: phantom-typed handles (`string<found!>`,
`<user-known!>`, `<held!>`), borrow-vs-consume obligations, auto-discharge
on hang-up, fabricated-ID refusal at wire level. Proven on the ledger
domain Sept 13 (frag-second-vocabulary); authored for airline Oct 19;
never flown on a tau2 task until 2026-11-13 — because every run
defaulted to the transliterated scope and nobody checked the env var.

First paired data point: task-0 native = 1.0 (DB+COMMUNICATE), the task
that scored 0.0 four times transliterated. n=1 — the measure.py
paired-trials campaign decides, not this sentence.

The durable rule: when two arms exist — transliteration vs native —
the transliteration is the control, never the default. An experiment
that never sets the scope variable measures the wrong system and calls
it the system.
